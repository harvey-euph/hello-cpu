# 深入解析 CPU 旗標（CPU Flags）：x86-64 與 ARM64 完整對比指南

在 CPU 的微架構中，**旗標暫存器（Flags Register）**是連接「算術/邏輯運算」與「控制流程跳轉（條件分支）」的橋樑。

無論高階語言中的 `if-else`、`while` 迴圈多麼複雜，在硬體底層，CPU 都只是在做兩件事：
1. **執行運算並在狀態暫存器中「立起旗標」**。
2. **根據旗標的數值決定要不要跳轉（Branch）**。

---

## 一、四大核心條件旗標（Condition Flags）

在幾乎所有現代架構中，最核心的都是這四個狀態旗標：

| 旗標名稱 | x86-64 名稱 | ARM64 名稱 | 觸發條件（何時為 1） | 典型用途 |
| :--- | :---: | :---: | :--- | :--- |
| **零旗標 (Zero)** | **`ZF`** | **`Z`** | 運算結果**完全等於 0** | 判斷相等（`==`）、迴圈計數減到 0 |
| **負數/符號旗標 (Negative / Sign)** | **`SF`** | **`N`** | 運算結果的最高位 (MSB) 為 1（有號數為負） | 判斷小於 0（`< 0`） |
| **進位旗標 (Carry)** | **`CF`** | **`C`** | 無號數加法溢出（或減法借位） | **無號數比較（Unsigned）**、大數高精度加減 |
| **溢位旗標 (Overflow)** | **`OF`** | **`V`** | 二補數**有號數**運算產生超出範圍的溢出 | **有號數比較（Signed）**、數學溢出偵測 |

### 核心觀念：CF 與 OF 的本質區別
CPU 本身在做加法時，**根本不知道你放進去的是有號數還是無號數**，它只是盲目地執行二進位加法，並同時更新這兩個旗標：
* **`CF`（Carry）**：將兩數視為**「無號數（Unsigned）」**。如果加法超過暫存器容量（例如 8-bit 的 `255 + 1 = 256`），則 `CF = 1`。
* **`OF`（Overflow）**：將兩數視為**「有號數（Signed，二補數）」**。如果正數+正數變成負數，或負數+負數變成正數（符號位錯亂），則 `OF = 1`。

## 二、x86-64 vs. ARM64（AArch64）的重大架構差異

雖然兩者都有四大條件旗標，但在**硬體設計哲學**與**具體行為**上存在巨大差異：

```text
x86-64 (CISC 哲學)              ARM64 (RISC 哲學)
─────────────────────────       ─────────────────────────
暫存器: RFLAGS                  暫存器: PSTATE / NZCV
更新方式: 絕大多數指令隱式更新   更新方式: 顯式更新 (必須帶 'S' 後綴)
減法借位: CF = 1 代表借位       減法借位: C = 0 代表借位 (無借位為 1)
```

---

### 差異 1：減法時的進位旗標（最著名的顛倒陷阱！）

這是在編寫跨平台組譯碼、虛擬機或模擬器（如 QEMU、Rosetta 2）時**最容易踩雷的第一大坑**：

#### 運算式：$A - B$（以 8-bit 為例，計算 $3 - 5$）

* **在 x86-64 中（Borrow 語意）**：
  * 當 $A < B$ 時，不夠減，需要「借位」。
  * **借位發生時：`CF = 1`**。
  * 沒有借位時：`CF = 0`。
* **在 ARM64 中（Carry 語意，反相！）**：
  * ARM 硬體內部是透過加法器做減法：$A - B = A + (\sim B) + 1$。
  * **沒有借位時（$A \ge B$）：`C = 1`**。
  * **發生借位時（$A < B$）：`C = 0`**。

```text
比較運算 (3 - 5)：
  x86-64 : CF = 1  (因為產生了 Borrow)
  ARM64  : C  = 0  (因為沒有 Carry-out，代表需要 Borrow)
```

---

### 差異 2：旗標更新方式（隱式自動更新 vs. 顯式選擇更新）

#### x86-64：絕大多數指令「強制隱式更新旗標」
在 x86-64 中，幾乎所有算術與邏輯指令（`add`, `sub`, `and`, `or`, `shr`）都會自動覆蓋 RFLAGS：
```assembly
# x86-64
add eax, ebx       # 會自動覆蓋 ZF, SF, CF, OF
inc eax            # 會覆蓋 ZF, SF, OF (但故意保留 CF)
```
* **後果**：當你需要保留算到一半的進位時，傳統 x86 指令極容易「不小心踩死前一個指令的旗標」。這也是為什麼 Intel 後來必須發明 `adcx`（只改 CF）與 `adox`（只改 OF）來救場。

#### ARM64：預設不更動旗標，除非加上 `S` 後綴（Explicit）
在 ARM64 中，標準指令**預設完全不碰旗標**！只有在指令後方加上 **`s`**（Set Flags）時才會更新：
```assembly
// ARM64 (AArch64)
add  x0, x1, x2     // 純加法：完全不影響 NZCV 旗標！
adds x0, x1, x2     // 帶 S 加法：才會更新 NZCV 旗標！

sub  x0, x1, x2     // 純減法：不影響旗標
subs x0, x1, x2     // 帶 S 減法：更新旗標 (cmp 就是 subs xzr, x1, x2 的別名)
```
* **優勢**：編譯器可以將計算與比較指令自由調度排列，不用擔心旗標被意外衝刷。

---

### 差異 3：條件分支與條件選擇（Branch & Select）

#### A. 條件分支跳轉
兩者在比較之後的條件跳轉助記符非常相似：

| 意圖（在 cmp A, B 之後） | 條件依據 | x86-64 指令 | ARM64 指令 |
| :--- | :--- | :---: | :---: |
| 相等 ($A == B$) | $Z == 1$ | `je` | `b.eq` |
| 不相等 ($A \ne B$) | $Z == 0$ | `jne` | `b.ne` |
| 無號數大於 ($A > B$) | $C == 0 \text{ 且 } Z == 0$ (x86)<br>$C == 1 \text{ 且 } Z == 0$ (ARM) | `ja` | `b.hi` |
| 無號數小於 ($A < B$) | $CF == 1$ (x86) / $C == 0$ (ARM) | `jb` | `b.lo` |
| 有號數大於 ($A > B$) | $Z == 0 \text{ 且 } S == O$ | `jg` | `b.gt` |
| 有號數小於 ($A < B$) | $S \ne O$ | `jl` | `b.lt` |

#### B. 避免分支預測失敗的條件移動
為了避免 CPU 分支預測錯誤（Branch Misprediction）的懲罰：
* **x86-64** 使用 `cmovcc`（Conditional Move）：
  ```assembly
  cmp  eax, 10
  cmovz eax, edx     # 若相等則將 edx 搬給 eax
  ```
* **ARM64** 擁有更豐富的條件選擇指令群：
  ```assembly
  cmp  w0, 10
  csel w0, w1, w2, eq   // 若相等 w0 = w1，否則 w0 = w2
  cinc w0, w1, eq       // 若相等 w0 = w1 + 1，否則 w0 = w1
  cset w0, eq           // 若相等 w0 = 1，否則 w0 = 0
  ```

#### C. ARM64 特有的「免旗標跳轉指令」
ARM64 提供了一批完全不依賴、也不修改條件旗標的高速跳轉指令：
* `cbz x0, label`：若暫存器 `x0 == 0` 則跳轉（Compare and Branch on Zero）。
* `cbnz x0, label`：若暫存器 `x0 != 0` 則跳轉。
* `tbz x0, #3, label`：測試 `x0` 的第 3 個 bit，若為 0 則跳轉（Test Bit and Branch）。

---

### 差異 4：旗標暫存器的硬體結構與存取

#### x86-64：`RFLAGS`（64 位元）
除了條件旗標外，x86 的 `RFLAGS` 還塞了許多歷史遺產與系統控制位元：
* **`PF`（Parity Flag，奇偶旗標）**：計算低 8 位元中 1 的個數是否為偶數（Intel 8080 遺留下來的古董）。
* **`DF`（Direction Flag，方向旗標）**：控制 `movsb`/`lodsb` 字串搬移指令是由低向高還是由高向低（`cld`/`std`）。
* **`IF`（Interrupt Flag，中斷旗標）**：是否允許硬體中斷（`cli`/`sti`）。
* **讀寫方式**：透過堆疊 `pushfq` / `popfq`，或傳統指令 `lahf` / `sahf`。

#### ARM64：`PSTATE`（Process State）與 `NZCV` 暫存器
ARM64 將架構清理得非常乾淨，移除了所有歷史包袱（無 PF、無 AF、無 DF）：
* 條件旗標被精確隔離在專用特殊暫存器 **`NZCV`** 中（位於 bit 31~28）：
  - Bit 31: `N`
  - Bit 30: `Z`
  - Bit 29: `C`
  - Bit 28: `V`
* **讀寫方式**：直接使用系統暫存器讀寫指令：
  ```assembly
  mrs x0, nzcv        // 讀取當前 NZCV 狀態至 x0
  msr nzcv, x0        // 將 x0 的數值寫回 NZCV
  ```

## 三、總結對比速查表

| 特性維度 | x86-64 | ARM64 (AArch64) |
| :--- | :--- | :--- |
| **狀態暫存器** | `RFLAGS` (64-bit) | `PSTATE` 中的 `NZCV` 暫存器 (bits 31:28) |
| **旗標更新策略** | **隱式（大部分指令自動更新）** | **顯式（必須主動加 `S` 後綴，如 `adds`）** |
| **減法借位邏輯** | **`CF = 1` 表示發生借位** | **`C = 0` 表示發生借位** (`C = 1` 為無借位) |
| **古董旗標 (PF, AF)** | 保留（相容 8086 / 8080 時代） | 完全剔除 |
| **字串操作方向 (DF)** | 有 (`std` / `cld`) | 無 |
| **條件選擇** | `cmovcc` | `csel`, `cinc`, `cset`, `csinv`, `csneg` |
| **免旗標跳轉** | 無（僅古董 `jrcxz`） | `cbz`, `cbnz`, `tbz`, `tbnz` |
| **暫存器直接讀寫** | 需透過 Stack (`pushfq`/`popfq`) | 專用暫存器指令 (`mrs`/`msr nzcv`) |
