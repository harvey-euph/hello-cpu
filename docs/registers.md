# x86 全系列暫存器大全與 45 年演進史：從 8086 到 APX 的硬體譜系

暫存器（Registers）是 CPU 微架構中距離運算單元（ALU）最近、延遲最低（通常為 0~1 個時脈週期）的超高速儲存單元。

自 1978 年 Intel 推出初代 16 位元處理器 8086 以來，x86 架構歷經了超過 45 年的演進。暫存器從最初的 **14 個 16 位元暫存器**，暴增擴展到今日涵蓋 64 位元通用整數、向量 SIMD（128/256/512 位元）、矩陣磁貼（AMX）、系統控制（CR/MSR）與除錯暫存器的**龐大硬體帝國**。

本文將系統性梳理 x86 全家族暫存器的**功能用途、二進位巢狀結構、命名由來與跨越近半世紀的演進歷史**。

## 一、x86 暫存器演進全景編年史（1978 ~ 2024+）

x86 架構的暫存器擴充不是推倒重來，而是**層層包裹、完全向下相容**的「俄羅斯套娃」式演進：

```text
45 年暫存器硬體擴展史:
┌─────────────────────────────────────────────────────────────────────────────────────────────────┐
│ 1978 (8086, 16-bit)   : AX, BX, CX, DX, SP, BP, SI, DI, IP, FLAGS, CS, DS, SS, ES              │
│ 1982 (80286, 16-bit)  : + 保護模式支援 (GDTR, IDTR, LDTR, TR, MSW)                             │
│ 1985 (80386, 32-bit)  : + 擴展 32-bit (EAX..EDI, EIP, EFLAGS), FS, GS, CR0..CR3, DR0..DR7       │
│ 1989 (80486)          : + 內建 x87 FPU 浮點堆疊 (ST0 ~ ST7)                                     │
│ 1993 (Pentium)        : + MSR 體系, CR4, 64-bit 硬體計時器 TSC                                  │
│ 1997 (Pentium MMX)    : + 64-bit 向量暫存器 MM0 ~ MM7 (借用 x87 實體)                           │
│ 1999 (Pentium III)    : + 128-bit 獨立向量暫存器 XMM0 ~ XMM7, MXCSR                             │
│ 2003 (AMD64, 64-bit)  : + 擴展 64-bit (RAX..RDI), 新增 R8 ~ R15, XMM8 ~ XMM15, CR8, RIP-rel    │
│ 2011 (Sandy Bridge)   : + 256-bit 向量暫存器 YMM0 ~ YMM15 (包容 XMM), XCR0                      │
│ 2013 (Xeon Phi/Skylake): + 512-bit 向量暫存器 ZMM0 ~ ZMM31, 遮罩暫存器 k0 ~ k7                   │
│ 2020 (Sapphire Rapids): + 矩陣乘法磁貼 TMM0 ~ TMM7 (8KB AMX Tile Architecture)                  │
│ 2023+ (Intel APX)     : + 通用暫存器翻倍為 32 個 (新增 R16 ~ R31, 3-operand ALU)                │
└─────────────────────────────────────────────────────────────────────────────────────────────────┘
```

## 二、通用暫存器（GPR）的演進與巢狀對映關係

通用暫存器（General-Purpose Registers）是日常程式執行、編譯器代碼生成、算術邏輯與記憶體定址的核心主力。

### 1. 16 位元初代架構（8086, 1978）：功能高度特化的 8 大暫存器
在 8086 中，每個暫存器都有明確的歷史命名與專屬硬體使命（承襲自 8 位元的 Intel 8080）：

* **`AX`（Accumulator）**：累加器。專門用於高效乘除法（`mul`, `div`）、I/O 埠存取（`in`, `out`）與特定字串操作。
* **`BX`（Base）**：基底暫存器。在 16 位元定址中，**只有 BX 和 BP 能用作基底定址指標**（如 `[bx + si]`）。
* **`CX`（Count）**：計數器。硬體專門為迴圈指令 `loop`、字串重複前綴 `rep` 與位移指令 `shl reg, cl` 綁定。
* **`DX`（Data）**：資料暫存器。配合 `AX` 存放 32 位元乘除法的溢位高位（`DX:AX`），以及存放 16 位元的 I/O 埠號。
* **`SP`（Stack Pointer）**：堆疊指標。指向當前堆疊頂端位址。
* **`BP`（Base Pointer）**：基底指標。專門用於棧幀（Stack Frame）訪問局部變數。
* **`SI`（Source Index）**：來源索引。字串複製指令（`movsb`, `lodsb`）的來源指標（`DS:SI`）。
* **`DI`（Destination Index）**：目的索引。字串複製指令（`stosb`）的目的指標（`ES:DI`）。

> [!NOTE]
> 前 4 個暫存器（`AX`, `BX`, `CX`, `DX`）可以拆解為獨立的兩個 8 位元暫存器使用：
> * 高 8 位（High）：`AH`, `BH`, `CH`, `DH`
> * 低 8 位（Low） ：`AL`, `BL`, `CL`, `DL`

### 2. 32 位元革命（80386, 1985）：延伸前綴 "E" 與正交化
80386 將上述暫存器拓寬至 32 位元，並在名稱前加上 **`E`（Extended）**：
`EAX`, `EBX`, `ECX`, `EDX`, `ESP`, `EBP`, `ESI`, `EDI`。

* **重大突破（正交定址）**：80386 取消了「只有 BX/BP 能定址」的硬體限制，引進了 **SIB 位元組**，所有通用暫存器都能用作 Base 與 Index（唯獨 ESP 不能當 Index）。

### 3. 64 位元長模式（AMD64, 2003）："R" 前綴與數量翻倍
AMD 推出 x86-64 時，做出了兩大關鍵革新：
1. **拓寬至 64 位元**：原有的 8 個暫存器前綴改為 **`R`（Register）**：`RAX`, `RBX`, `RCX`, `RDX`, `RSP`, `RBP`, `RSI`, `RDI`。
2. **數量直接翻倍**：新增了 8 個全新的 64 位元暫存器：**`R8` ~ `R15`**。
3. **低 8 位元存取全面解鎖**：透過 REX 前綴，解鎖了 `RSP`, `RBP`, `RSI`, `RDI` 的最低 8 位元：**`SPL`, `BPL`, `SIL`, `DIL`**。

### 4. 巢狀空間對映圖（以 RAX 與 R8 為例）

在實體晶片中，子暫存器並不是額外的硬體線路，而是 64 位元暫存器的低位切片（Slice）：

```text

├───────────────────────────────────┴───────────────────┴───────────┴───────────┤
│                                                       │       AX (16-bit)     │
```

## 三、指令指標（IP）與旗標暫存器（FLAGS）

這兩個暫存器控制著 CPU 的執行流程與狀態判定：

### 1. 程式計數器：`IP` $\to$ `EIP` $\to$ `RIP`
* **8086（16-bit）`IP`**：指向當前代碼段內的 16 位元偏移（搭配 `CS`）。
* **80386（32-bit）`EIP`**：32 位元線性虛擬位址。
* **x86-64（64-bit）`RIP`**：64 位元虛擬位址。
  * **重大特性：RIP 相對定址（RIP-relative addressing）**：
    在 64 位元長模式中，編譯器生成位置無關代碼（PIC/PIE）時，可以直接寫 `[rip + disp32]`，程式碼無論被作業系統載入至記憶體何處，都能以常數偏移量存取資料。

### 2. 旗標暫存器：`FLAGS` $\to$ `EFLAGS` $\to$ `RFLAGS`
記錄運算結果的狀態以及控制 CPU 的運作模式（高 32 位元在 64 位元模式下目前保留為 0）：

## 四、段暫存器（Segment Registers）的興衰史

段暫存器是 x86 歷史包袱中最沉重、但也最有趣的一部分。

### 1. 實模式時代（8086）：為突破 16-bit 定址而生
8086 只有 16 位元暫存器（最多定址 64KB），但外部位址匯流排有 20 位元（可存取 1MB）。  
為了解決這個矛盾，Intel 發明了**分段機制（Segmentation）**：
$$\text{物理位址} = (\text{段暫存器} \times 16) + \text{偏移暫存器}$$

當時有 4 個 16 位元段暫存器：
* **`CS`（Code Segment）**：程式碼段（搭配 `IP`）。
* **`DS`（Data Segment）**：預設資料段。
* **`SS`（Stack Segment）**：堆疊段（搭配 `SP`）。
* **`ES`（Extra Segment）**：額外資料段（搭配 `DI` 字串指令）。

### 2. 保護模式時代（80286 ~ 80386）：段選擇子與 GDT
80386 新增了 **`FS`** 與 **`GS`** 兩個通用額外段暫存器。  
此時段暫存器儲存的不再是記憶體基底，而是 **段選擇子（Segment Selector）**，指向記憶體中的全域描述元表格（GDT）。硬體會在這裡檢查特權級（Ring 0~3）、讀寫權限與邊界（Limit）。

### 3. 64 位元長模式（AMD64）：全面扁平化（Flat Memory Model）
在 64 位元模式下，虛擬位址空間達到驚人的 128TB（48-bit）甚至 4PB（57-bit），**分段機制被正式宣告淘汰**！
* **硬體強制歸零**：`CS`, `DS`, `ES`, `SS` 的段基底（Base Address）在硬體層級**被強制固定為 0**！所有記憶體存取視為單一平坦空間。

### 4. 倖存者的奇蹟：FS 與 GS 的現代新生
唯一在 64 位元長模式中仍然保有「非零基底」特權的段暫存器只有 **`FS`** 與 **`GS`**：
* **`FS`（Linux 的神經中樞）**：專門用於**執行緒區域儲存區（TLS, Thread Local Storage）**。  
  在 Linux 使用者空間中，`mov rax, fs:[0]` 可直接取得目前執行緒的 pthread 結構指標與 `errno`。
* **`GS`（Windows 與 Linux 核心的神器）**：
  * 在 Windows 64-bit 使用者空間：`gs:[0x30]` 指向執行緒環境區塊（TEB），`gs:[0x60]` 指向行程環境區塊（PEB）。
  * 在 Linux 核心模式：`GS` 指向目前 CPU 核心的 `per-cpu` 私有資料區。核心進入點透過特權指令 **`swapgs`**，瞬間將使用者空間與核心空間的 GS 基準指標原子互換！

> [!NOTE]
> 在 64 位元下，FS 與 GS 的 64 位元基底位址不再透過 GDT 表格設定，而是直接存入特定暫存器（MSR: `IA32_FS_BASE` / `IA32_GS_BASE`），或透過支援的指令 `rdfsbase` / `wrfsbase`（參見 [`src/demo/2012_fsgsbase.s`](src/demo/2012_fsgsbase.s)）高速讀寫。

## 五、浮點數與 SIMD 向量暫存器大爆發

當科學計算、多媒體處理、現代 3D 遊戲與 AI 推論崛起時，通用暫存器已無法負荷，x86 經歷了一波波震撼級別的向量暫存器擴充：

```text
SIMD 向量暫存器寬度倍增史:
80-bit  : ST(0) ~ ST(7)  [x87 FPU, 堆疊式]
64-bit  : MM0 ~ MM7      [MMX, 借用 x87]
128-bit : XMM0 ~ XMM15   [SSE ~ SSE4.2]
256-bit : YMM0 ~ YMM15   [AVX / AVX2]
512-bit : ZMM0 ~ ZMM31   [AVX-512, 新增 k0~k7 遮罩]
```

### 1. x87 FPU 堆疊暫存器（8087 ~ 80486）
* **`ST(0)` ~ `ST(7)`**：8 個 80 位元**延伸雙精度（Extended Precision）**浮點暫存器。
* **致命弱點**：它是**環形堆疊（Stack-based）**架構，而不是正交暫存器！所有運算都要 `fld`（壓棧）、`fstp`（彈棧），編譯器極其痛苦，暫存器配置器（Register Allocator）極難最佳化。

### 2. MMX（Pentium MMX, 1997）：借腹生子
* **`MM0` ~ `MM7`**：8 個 64 位元整數向量暫存器。
* **歷史妥協**：Intel 為了避免在作業系統行程切換時增加額外的 Context Switch 儲存成本，**直接把 MM0~MM7 硬生生對映在 x87 的 ST(0)~ST(7) 實體電路上**！
* **代價**：MMX 與浮點運算不能混用，退出 MMX 時必須執行昂貴的 `emms` 指令還原 x87 狀態。

### 3. SSE 家族（Pentium III, 1999 $\to$ Core 2, 2008）：獨立向量單元
* **`XMM0` ~ `XMM7`**（32 位元模式）/ **`XMM0` ~ `XMM15`**（64 位元模式）：
  * 獨立的 **128 位元** 暫存器檔案（Register File），不再借用 x87！
  * 可容納 4 個 32-bit 單精度浮點數（`float`）或 2 個 64-bit 雙精度浮點數（`double`）或 16 個 8-bit 整數。
* **控制暫存器：`MXCSR`**：
  * 控制 SSE/AVX 的捨入模式、除以零例外遮罩、Denormal 非正規數清零（FTZ, Flush-to-Zero）與 DAZ（Denormals-Are-Zero）。

### 4. AVX / AVX2（Sandy Bridge, 2011 $\to$ Haswell, 2013）：YMM 體系
* **`YMM0` ~ `YMM15`**：暫存器寬度翻倍為 **256 位元**！
* **包容對映**：`XMM` 成為 `YMM` 的低 128 位元切片。
* **VEX 前綴革命**：引入 3 運算元非破壞性指令語法（`vaddps ymm0, ymm1, ymm2`，不破壞來源運算元）。
* **VZEROUPPER 陷阱**：在 AVX 與 SSE 混用時，若未執行 `vzeroupper` 清除 YMM 高位，會引發數十萬個週期的管線罰時（詳見專案微基準測試 [`src/perf/2011_vzeroupper.s`](src/perf/2011_vzeroupper.s)）。

### 5. AVX-512（Xeon Phi / Skylake-SP, 2013~2017）：ZMM 巨獸
* **`ZMM0` ~ `ZMM31`**：暫存器寬度再次翻倍為 **512 位元**，且**數量翻倍為 32 個**！
  * 單一暫存器可同時塞入 16 個 32-bit 浮點數或 64 個 8-bit 字元！
* **專屬謂詞遮罩暫存器：`k0` ~ `k7`**：
  * 獨立的 16 位元 / 64 位元 Opmask 暫存器。
  * 支援 SIMD 條件分支向量化，精確控制 512 位元中哪些通道（Lanes）寫入、哪些通道保持原值（Zeroing / Merging Masking）。

```text
向量暫存器三層對映結構圖:

┌─────────────────────────────────────┬───────────────────────┬───────────────────────┐
│              ZMM0[511:256]          │      YMM0[255:128]    │      XMM0[127:0]      │
├─────────────────────────────────────┴───────────────────────┴───────────────────────┤
│                                     │                      YMM0 (256-bit)           │
```

## 六、人工智慧與矩陣加速：Intel AMX 暫存器

在第 4 代 Xeon 可擴充處理器（Sapphire Rapids, 2020+）中，Intel 引入了 **AMX（Advanced Matrix Extensions）**，專門用於大語言模型（LLM）與深度學習推論：

* **`TMM0` ~ `TMM7`（Tile 暫存器）**：
  * 8 個專屬的二維矩陣暫存器（磁貼）。
  * 每個 Tile 最大可達 **1KB（1024 Bytes）**，8 個暫存器合計高達 **8KB** 的片上超高速矩陣快顯記憶體！
* **`TILECFG`**：專門配置各個 TMM 磁貼的行數（Rows）與列數（Columns）維度大小。
* 搭配 **TMUL（Tile Matrix Multiply Unit）** 引擎，可在單一指令內完成龐大的 `INT8` 或 `BF16` 矩陣乘法運算。

這些暫存器只能在作業系統最高特權等級（Ring 0）下透過 `mov crX, reg` 讀寫，決定了 CPU 硬體的運行模式：

## 八、除錯與效能剖析暫存器（DR0 ~ DR7, TSC）

### 1. 硬體斷點除錯暫存器（`DR0` ~ `DR7`）
這就是為什麼除錯工具（如 GDB, LLDB, WinDbg）不需要修改程式碼記憶體就能下「硬體執行斷點」與「記憶體讀寫監控點（Watchpoint）」的秘密：

* **`DR0` ~ `DR3`**：4 個 64 位元線性虛擬位址暫存器，存放 4 個硬體斷點的位址。
* **`DR4`, `DR5`**：保留（由 CPU 硬體重定向至 DR6/DR7）。
* **`DR6`（Debug Status Register）**：狀態暫存器。當中斷 `#DB` 觸發時，指出是哪一個斷點命中。
* **`DR7`（Debug Control Register）**：控制暫存器。精細設定各斷點是「指令執行斷點」、「記憶體寫入斷點」還是「讀寫皆中斷」，以及監控寬度（1, 2, 4, 8 Bytes）。

### 2. 時間戳計數器：`TSC`（Time Stamp Counter）
* **`TSC`**（64-bit）：CPU 自開機以來經過的時脈週期總數。
* 指令 `rdtsc` / `rdtscp`：可在使用者空間以極低延遲（~20 週期）讀取奈秒級時間戳（參見專案微基準測試 [`src/perf/2008_rdtscp.s`](src/perf/2008_rdtscp.s)）。

## 九、特定型號暫存器（MSR, Model-Specific Registers）

MSR 是 x86 核心最具威力的控制通道（共數千個），透過特權指令 **`rdmsr`** 與 **`wrmsr`**（指定 `ECX` 暫存器為 MSR 位址，`EDX:EAX` 傳遞 64 位元數值）進行存取：

### 關鍵 MSR 清單（系統工程師必知）

| MSR 名稱 | MSR 位址 | 核心職責 |
| :--- | :---: | :--- |
| **`IA32_EFER`** | `0xC0000080` | **擴展功能致能暫存器**：啟用長模式（LME, Long Mode Enable）、啟用 `syscall`（SCE）。 |
| **`IA32_STAR`** | `0xC0000081` | 存放 32-bit 與相容模式 `syscall` 的目標段選擇子。 |
| **`IA32_LSTAR`** | `0xC0000082` | **64-bit syscall 目標入口位址**（CPU 執行 `syscall` 時自動跳入該 RIP）。 |
| **`IA32_FMASK`** | `0xC0000084` | 執行 `syscall` 時自動從 `RFLAGS` 遮蔽（清零）的旗標遮罩（通常遮蔽 IF、DF）。 |
| **`IA32_FS_BASE`** | `0xC0000100` | 64 位元 `FS` 段基底位址（TLS 指標）。 |
| **`IA32_GS_BASE`** | `0xC0000101` | 64 位元 `GS` 使用者態基底位址。 |
| **`IA32_KERNEL_GS_BASE`**| `0xC0000102` | 核心態 GS 基底位址（`swapgs` 互換暫存區）。 |
| **`IA32_SPEC_CTRL`** | `0x00000048` | **推測執行硬體防禦**：控制 IBRS（Spectre v2 防護）與 STIBP。 |
| **`IA32_MISC_ENABLE`**| `0x000001A0` | 控制硬體預取器（Hardware Prefetcher）、SpeedStep 動態調頻。 |

## 十、系統描述元表格暫存器（GDTR, IDTR, LDTR, TR）

作業系統管理記憶體結構與中斷向量的四大專屬硬體指標：

* **`GDTR`（Global Descriptor Table Register）**：
  * 存放全域描述元表格（GDT）的基底位址與長度上限（Limit）。
  * 透過特權指令 `lgdt` 載入。
* **`IDTR`（Interrupt Descriptor Table Register）**：
  * 存放中斷描述元表格（IDT）的基底位址與長度上限。
  * 決定 CPU 遭遇中斷（如除以零、分頁錯誤）或外部硬體 IRQ 時該跳往何處執行。透過 `lidt` 載入。
* **`LDTR`（Local Descriptor Table Register）**：
  * 存放局部描述元表格選擇子。透過 `lldt` 載入。
* **`TR`（Task Register）**：
  * 存放當前任務狀態區段（TSS, Task State Segment）的選擇子。
  * 在 64 位元模式下，TSS 儲存了核心堆疊指標（RSP0）與中斷堆疊表（IST），透過 `ltr` 指令載入。

## 十一、下個世代的變革：Intel APX（32 個通用暫存器）

在 2023 年，Intel 正式公佈了 **Intel APX（Advanced Performance Extensions）**，這是 x86 通用暫存器自 2003 年以來最震撼的革命：

```text
Intel APX 架構大升級:
通用暫存器數量: 16 個 ───────> 32 個！
新增暫存器:     R16, R17, R18, R19, R20, R21, R22, R23,
               R24, R25, R26, R27, R28, R29, R30, R31
```

### APX 帶來的四大核心優勢：
1. **通用暫存器翻倍為 32 個**：
   * 追平 ARM64（AArch64 的 31 個通用暫存器）與 RISC-V。
   * 大幅減少繁重運算中的暫存器溢出溢出壓棧（Spill to Stack），編譯器估計可減少 10%~20% 的記憶體載入/儲存操作。
2. **引進 3 運算元非破壞性整數指令（NDD, Non-Destructive Destination）**：
   * 以前：`add rax, rbx` 會直接覆寫 `rax`。
   * 現在：`add r16, rax, rbx`（直接將結果存入 `r16`，保持來源暫存器不變，類似 RISC 語法语境）。
3. **條件比較指令（CCMP / CTEST）**：
   * 允許鏈式條件判斷，大幅消除多重分支條件判斷（Short-circuit evaluation）帶來的小跳躍。
4. **REX2 / EVEX 增強前綴**：
   * 利用擴展前綴中的新位元擴展第 5 個 bit（存取 0~31 號暫存器）。
